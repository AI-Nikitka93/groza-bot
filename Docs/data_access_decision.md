# Personal Pocket Lightning Rod: Data Access & Infrastructure Decision v2.0
Дата: 2026-07-02
Таймзона: +03:00

## Scope
- Что именно исследовано: Углубленный поиск альтернативных источников молний, баз данных с поддержкой PostGIS, хостингов 24/7 для воркеров и детальных лимитов Threads API.
- Какой режим: DEEP DIVE (Повторный анализ консилиумом из 5 агентов, июль 2026).

## Краткий вывод
Первоначальный стек был существенно пересмотрен в пользу большей надежности и огромного увеличения лимитов:
1. **База данных:** Замена Supabase (500 МБ) на **Tembo** (10 ГБ) с применением `MULTIPOINT` кластеризации.
2. **Хостинг воркера:** Переход на **Serv00.com** (честные 24/7 процессы) или **HuggingFace Spaces** (16 ГБ RAM + cron ping). 
3. **Молнии:** Альтернатив **Blitzortung** в реальном времени не существует. Требуется паттерн **MQTT Proxy** (Single-Worker).
4. **Threads API:** Автопостинг возможен, но требует публичного URL для картинок (двухшаговая загрузка) и рандомизации текстов от спам-фильтров Meta.

## Текущий консенсус и выбор стека (Zero-Cost 2.0)

### 1. Источники данных о молниях
- **Primary: Blitzortung (WebSocket) + MQTT Proxy.** 
  - Альтернативных strike-by-strike API с задержкой < 90с в природе не существует (остальные либо закрытые Enterprise, либо 10-мин растры).
  - Строгое правило: Прямой коннект ботов пользователей запрещен. Мы обязаны поднять *единственный* фоновый воркер-прокси, который декодирует WebSocket и пишет в нашу БД (Tembo/Redis).

### 2. Вещание (Threads API & Карты)
- Лимит в 250 постов/день. Минимальный rate-limit API: 48,000 вызовов/сутки.
- **Подводные камни:**
  - *Бан за спам:* Жесткие AI-фильтры Meta банят за `rapid-fire` публикацию идентичного текста. Обязательна рандомизация (хэши, синонимы, таймстемпы) и паузы (pacing).
  - *Картинки:* Загрузка двухшаговая (Сначала передаем публичный URL на Image Hosting -> получаем `container_id` -> публикуем пост). Нет поддержки multipart/form-data. Нет метода Delete для постов через API.

### 3. Инфраструктура
- **БД (ГИС): Tembo (Hobby Tier)**
  - Дает **10 GB** диска и 1 GB RAM, полная поддержка PostGIS.
  - *Экстремальное сжатие:* Переход от `POINT` к `MULTIPOINT` / `pgPointcloud`. Использование легковесных **BRIN** индексов вместо GiST (time-series). Снижение точности координат (quantization), что позволяет сжимать 10 млн молний до 150 МБ.
- **Очереди: Upstash Redis Free Tier**
  - Подтверждено: 500k команд в месяц. С лихвой хватает для кэширования и Rate Limiting (дедупликации).
- **Workers/API: Serv00.com или HuggingFace Spaces**
  - Serv00.com дает бесплатный 24/7 доступ по SSH без сна. Лимит 15 процессов. 
  - HuggingFace Spaces дает 16GB RAM Docker (засыпает через 48ч, нужен пинг 1 раз в день).

## Практические выводы
Новый сверхнадежный стек (Blitzortung Proxy -> Tembo -> Serv00/HF -> Threads) решает все инфраструктурные ограничения $0 бюджета. Особое внимание придется уделить рандомизатору текстов для обхода спам-фильтров Meta и организации публичного хостинга сгенерированных карт молний (например, Imgur API).
